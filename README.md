# Gemini Nexus

סביבת שיחות בעברית, במראה בהשראת Gemini, עם שרת API מאוחד וממשק Blazor WebAssembly לדפדפן.

## 1. מימוש נוכחי

- ארבעה פרויקטי מוצר: Shared, UI, Server ו־Client.Wasm; המימוש הנוכחי הוא .NET 10 / C# 14 וגרסת ה־SDK נעולה ב־global.json. יעד השדרוג ל־.NET 11 / C# 15 מוגדר בסעיף 2.20. Client.Wasm נדרש ליצירת חבילת הדפדפן, אך אינו מופעל כשרת עצמאי.
- אימות Cookie עם סשנים ניתנים לביטול, ניהול משתמשים והחלפת סיסמה, בדיקת בעלות בכל גישה לשיחה ולריצה, הגנת בקשות משנות מצב והגבלת קצב נפרדת להתחברות. סודות נקראים מסביבת התהליך או מקובץ חיצוני.
- שיחות שמורות, שני צדדי השיחה, חיפוש כותרות, נעיצה, ארכוב, עריכה באמצעות הסתעפות והקשר שנשלח בפועל למודל.
- תור מתמשך במסד הנתונים עם Outbox, תזמון Channels מוגבל, ביטול, מכסות מקביליות, פעימות חיות ושחזור תשובה חלקית לאחר אובדן תהליך. ריצה שנקטעה אינה נוצרת מחדש אצל הספק אוטומטית.
- הזרמת SSE עם מספרי רצף וחיבור מחדש, חלונית אירועים גולמיים ונתוני שימוש מדווחים שנשמרים גם לאחר פינוי אירועי הדיבאג, כולל זמן לתוכן ראשון, זמן בתור וזמן עיבוד. סיום הריצה, אירוע הסיום והתשובה נשמרים בעסקה אחת.
- עימוד הודעות דו־כיווני ושיחות, טעינה מוקדמת לפי כיוון הגלילה, באפר הודעות מוגבל, גלילה וירטואלית, עוגן גלילה וגלילה לתחתית בהתאם למיקום המשתמש.
- עד עשרה קבצים בקלט: העלאה זורמת ל־Gemini Files API, עד 100MB לקובץ ועד 50MB ל־PDF, שמירת הפניה לפי משתמש ובדיקת בעלות בכל שליחה. קלט inlineData ישן עדיין נתמך לתאימות.
- תוספי פרומפט דטרמיניסטיים: prefix, suffix, system, replace. הגדרות מסונכרנות, וביצוע בשרת או בלקוח.
- מתאם generateContent, קטלוג מודלים וספירת טוקנים רשמית הכוללת הוראות מערכת וכלים. מעבדת API למנהל עבור בקשות JSON חד־פעמיות.
- סרגל השיחה מציג את כל קטלוג `models.list` במדרג סוג יכולת, משפחה ומודל/גרסה. מודלי תמונה, כולל Nano Banana, אינם מסוננים עוד; מודלים חדשים שאינם מוכרים מוצגים תחת ״לא סווג״. מודל שאינו תומך `generateContent` נשאר גלוי אך אינו ניתן לשליחה כשיחה רגילה. הסרגל מציע גם רמת חשיבה אוטומטית, מינימלית, נמוכה, בינונית או גבוהה. ההגדרה מתורגמת ל־`thinkingLevel` ב־Gemini 3 ול־`thinkingBudget` ב־Gemini 2.5.
- מסך יכולות ופעולות שמורות עבור Interactions,‏ Embeddings,‏ Batch,‏ Files,‏ Cache,‏ Media ו־Operations, וכן שער WebSocket מאומת ומוגבל ל־Live API. העלאת קובץ מרוחק משתמשת בפרוטוקול resumable בלי לחשוף את מפתח הספק ללקוח.
- קריאות כלים רב־סבביות עם כלים מובנים וחבילות WASI מבודדות בתהליך `wasmtime`. ה־manifest, ההרשאות, הגרסה, hash החבילה ותוצאות ההפעלה נשמרים במסד הנתונים.
- הגירות סכימה ממוספרות, נעילת הגירה ב־PostgreSQL, תביעת עבודות עם `SKIP LOCKED` ונעילות advisory לריבוי מופעים. קיימת בדיקת קבלה ייעודית לשני שרתים מול PostgreSQL.
- איפוס סיסמה חד־פעמי בדוא״ל, מדיניות שימור, גיבוי ושחזור ל־SQLite/PostgreSQL, ו־health readiness הכולל גרסת סכימה ועומק תור.
- יעד פרסום NativeAOT ל־Linux ורכיב C++ דרך `LibraryImport`, מסלול SIMD ללא הקצאות שנמדד בבדיקה, זיכרון Native מיושר ומסלול OpenCL מפורש עם דיווח כאשר GPU אינו זמין.

## 2. חזון מאוחד, מטרות ויעדי־על

> פרק זה מגדיר את **מצב היעד** של Gemini Nexus. התיאור הקיים ב־README של המימוש הנוכחי נשאר מקור האמת למצב שכבר הושלם. יכולת שמופיעה כאן אינה נחשבת לממומשת עד שהקוד, הבדיקות והתיעוד מאשרים זאת.

### 2.1 חזון המוצר

Gemini Nexus מיועד להיות סביבת AI פרטית, עצמאית ובאירוח עצמי, הנגישה מהדפדפן בלבד. השרת הוא נקודת השליטה היחידה: הוא מנהל שיחות, מודלים, קבצים, Workspaces, גרסאות, כלים, משימות, תורים, הרשאות, סודות, תצפיות וחיבור לספקי AI. הדפדפן מספק ממשק WASM מהיר ויכול, באישור מפורש של המשתמש, לתווך גישה לתיקיות מקומיות בלי להעלות אותן בשלמותן.

המוצר צריך לאחד חמש חוויות במערכת אחת:

1. ממשק שיחה מתקדם בהשראת Gemini.
2. AI Gateway מאובטח מול Gemini וספקים עתידיים.
3. סביבת עבודה לפרויקטים, קבצים, Artifacts וגרסאות.
4. מערכת Agents, כלים ותוספים עם Sandbox מבוקר.
5. מנוע חכם לצמצום הקשר, טוקנים, עלות וזמן תגובה.

### 2.2 עקרונות מחייבים

- **דפדפן בלבד:** אין לקוח MAUI, אפליקציה שולחנית או לקוח נפרד. כל חוויית המשתמש והניהול מתבצעת בדפדפן.
- **פורט יחיד:** כל רכיבי המוצר נגישים פנימית דרך `https://localhost:5000` בלבד. אין פורטי פיתוח או פרודקשן נוספים למוצר.
- **Origin יחיד:** ה־WASM, ה־REST API, ה־SSE, ה־WebSocket, ההורדות, ההעלאות ובדיקות הבריאות פועלים מאותו Host, Scheme ו־Port.
- **שרת יחיד ולוגיקה מאוחדת:** אין לפצל שירותים, תהליכים או שכבות קוד אלא כאשר קיימת הצדקה תפעולית, אבטחתית או ביצועית מדידה.
- **אירוח עצמי ופרטיות תחילה:** נתונים נשמרים מקומית כברירת מחדל; כל העברה לספק חיצוני מוצגת למשתמש ומתבצעת רק לפי בחירתו.
- **משתמש יחיד:** אין מערכת רישום, Tenants, ארגונים או ניהול משתמשים מרובים. שם משתמש וסיסמה יחידים מגינים על המערכת.
- **ניהול מתוך המוצר:** הגדרות, API Keys, ספקים, אחסון, Workspaces, כלים, תוספים, מכסות, גיבויים ונתוני תפעול מנוהלים מתפריט ניהול בדפדפן.
- **שקיפות:** לפני פעולה יוצגו היעד, הקבצים המעורבים, הספק, המודל, ההרשאות, ההקשר, העלות המשוערת וההשפעה האפשרית.
- **אישור לפני שינוי:** כתיבה לקבצים, הפעלת פקודות, התקנת תוסף, גישה לרשת או שליחה לענן דורשות מדיניות ואישור מתאימים.
- **התאוששות מלאה:** רענון דפדפן, ניתוק רשת או אתחול שרת לא יאבדו שיחה, משימה, אירוע, Artifact או שינוי מאושר.

### 2.3 ארכיטקטורת יעד ופורט 5000

השרת הוא Host מאוחד שמגיש את קובצי Blazor WASM ומארח את כל שירותי ה־Backend:

| נתיב יעד | תפקיד |
|---|---|
| `/` | ממשק העבודה והניהול ב־Blazor WASM |
| `/api/*` | REST API |
| `/api/runs/{id}/events` | SSE עם חיבור מחדש ומספרי רצף |
| `/api/live` | WebSocket ל־Gemini Live ולתקשורת דו־כיוונית עם הדפדפן |
| `/api/workspaces/*` | קבצים, אינדוקס, גרסאות, Diffs ו־Artifacts |
| `/health/live` | חיות התהליך |
| `/health/ready` | מסד נתונים, סכימה, תור, אחסון ותלויות מחייבות |

דרישות מחייבות:

- השרת מאזין על פורט `5000` בלבד בכל פרופילי ההרצה.
- לא יישמרו פרופילי Standalone שמפעילים WASM בפורטים `5148`, `7108` או בכל פורט אחר.
- אין Caddy, Nginx או Reverse Proxy בתוך המאגר. מפעיל המערכת רשאי להפנות מבחוץ דומיין ב־443 אל 5000.
- אין תלות ב־CORS בתרחיש הרגיל, מפני שכל רכיבי המוצר עובדים מאותו Origin.
- הפעלת Visual Studio, `dotnet run`, פרסום NativeAOT ובדיקות קבלה משתמשים כולם באותה כתובת לוגית.
- Redirects, כתובות Callback וקישורים מוחלטים נגזרים מכתובת ציבורית מוגדרת ולא מפורטים קשיחים.
- הפריסה היא יחידתית כברירת מחדל; Scale-out אפשרי בעתיד רק בלי לשנות את חוזי הלקוח או עקביות הנתונים.

### 2.4 לקוח Web ו־WASM

- `GeminiNexus.Client.Maui` הוסר מהפתרון, מה־CI, מהסקריפטים ומהתיעוד התפעולי.
- `GeminiNexus.Client.Wasm` הוא הלקוח היחיד.
- `GeminiNexus.UI` נשאר Razor Class Library רק כאשר הוא מפחית כפילות אמיתית; אין לשמור הפשטות שאין להן צרכן נוסף או ערך בדיקות ברור.
- השרת מגיש את פלט ה־WASM בעצמו, כולל fallback ל־`index.html`, קבצים דחוסים, Cache headers וגרסאות נכסים.
- יש לתמוך ב־WASM AOT כאשר הוא יציב ומתאים, ב־lazy loading ובפיצול חבילות כדי לקצר זמן טעינה.
- רינדור רשימות שיחות, הודעות, קבצים, אירועים ו־Artifacts יהיה וירטואלי ומדורג.
- הלקוח לא יחזיק את כל ההיסטוריה או את כל עץ הפרויקט בזיכרון.
- משימות פעילות ממשיכות בשרת גם כשהטאב נסגר; לאחר חזרה הלקוח משחזר מצב ואירועים.
- יש לתמוך ב־PWA, התקנה אופציונלית, Service Worker ועדכוני גרסה בטוחים, בלי להפוך את המוצר ללקוח נפרד.
- הממשק יהיה Responsive, נגיש במקלדת, מותאם RTL ועברית, וערוך גם ל־LTR ולאנגלית.
- פעולות ארוכות יציגו התקדמות, שלב נוכחי, אפשרות ביטול, Retry ושחזור תצוגה.

### 2.5 מבנה הפרויקטים ופישוט הקוד

מצב היעד הוא ארבעה פרויקטי מוצר בלבד:

| פרויקט | אחריות |
|---|---|
| `GeminiNexus.Shared` | חוזים, טיפוסים משותפים, Serialization source generation וכללים דטרמיניסטיים |
| `GeminiNexus.UI` | רכיבי Razor ושירותי UI שיש להם ערך משותף ברור |
| `GeminiNexus.Server` | Host, API, אימות, מסד, תורים, ספקים, Workspaces, Agents וכלים |
| `GeminiNexus.Client.Wasm` | Bootstrap של הדפדפן, אחסון לקוח והרשאות Browser APIs |

עקרונות:

- MAUI, פרופילי ההרצה הכפולים ורכיבי UI לא־בשימוש שכבר זוהו הוסרו; יש להמשיך להסיר קוד מת רק לאחר הוכחת היעדר שימוש ובדיקת רגרסיה.
- לשמור חוזים משותפים קטנים ויציבים; לא להעביר ל־Shared לוגיקה ששייכת לשרת.
- להשתמש ב־DI ובגבולות ברורים, אך להימנע מ־Microservices, שכבות מעבר ריקות וממשקים בעלי מימוש יחיד ללא צורך בדיקות או החלפה.
- לאחד מסלולי שיחה, משימה ופעולה סביב מודל Run עקבי במקום מנגנונים מקבילים.
- להשתמש ב־CQRS, REPR ו־DDD במקומות שבהם הם מבהירים בעלות, עקביות וזרימת מידע; לא לייצר טקסיות ללא ערך.
- כתיבות עסקיות מתמשכות משתמשות בעסקאות וב־Outbox כאשר נדרש פרסום אירוע אמין.

### 2.6 משתמש יחיד, כניסה וניהול

- קיימת זהות בעלים יחידה, לדוגמה `admin`; אין Endpoint ליצירת משתמשים ואין מסך רשימת משתמשים.
- אין הרשמה עצמית, הזמנות, תפקידי משתמש או הפרדת Tenant.
- שם המשתמש והסיסמה נועדו למנוע גישה לא מורשית, לא לנהל קהילה.
- סיסמה נשמרת רק כ־hash חזק ומומלח; אין אפשרות לקרוא אותה חזרה.
- יש לתמוך בשינוי סיסמה, ביטול כל הסשנים, נעילה זמנית לאחר ניסיונות כושלים וקודי שחזור חד־פעמיים.
- Cookies יהיו `HttpOnly`, `Secure` בפרודקשן ו־`SameSite=Strict`.
- כל פעולה משנת מצב מוגנת מפני CSRF ונבדקת מול Session פעיל.
- תפריט ראשי מפריד בין **עבודה** לבין **ניהול**, בלי להפעיל אתר ניהול או פורט נפרדים.
- אזור הניהול כולל לפחות:
  - Gemini API Key וספקי AI נוספים.
  - בדיקת תקינות חיבור ללא חשיפת הסוד.
  - מודלים מותרים, ברירות מחדל ורמות חשיבה.
  - אחסון, מסד נתונים, נתיבי Workspaces ומדיניות שימור.
  - מגבלות ספק, תקציבים והתראות.
  - כלים, Plugins, Connectors והרשאות.
  - תורים, משימות פעילות, שגיאות, Audit וטלמטריה.
  - גיבוי, שחזור, ייצוא ומחיקה.
  - אבטחה, Session, סיסמה ומפתחות הצפנה.
- API Keys יוצגו לאחר שמירה כמוסתרים בלבד; עדכון שלהם יירשם ב־Audit ללא הערך.
- Bootstrap ראשוני יאפשר להגדיר בעלים ומפתח API בבטחה מהדפדפן, ורק כאשר המערכת טרם אותחלה ובכפוף להוכחת גישה מקומית או Token חד־פעמי.

### 2.7 Workspaces, וירטואליזציה של נתיב וגרסאות

Workspace הוא ייצוג לוגי של פרויקט או אוסף קבצים, בלי תלות במקום שבו התוכן נמצא.

כל Workspace כולל:

- מזהה יציב, שם, סוג מקור, שורש לוגי ומדיניות הרשאות.
- עץ קבצים וירטואלי מנורמל שאינו חושף נתיבים מחוץ לשורש שאושר.
- Metadata: גודל, MIME, hash, זמן שינוי, Encoding, שפה וסוג קובץ.
- אינדקס טקסט, סמלים, מחלקות, פונקציות, Imports ותלויות.
- Repository map ותקצירים היררכיים ברמת פרויקט, תיקייה, קובץ וסמל.
- היסטוריית Snapshots, גרסאות, Diffs, Patches ו־Artifacts.
- סטטוס קבצים: נוסף, שונה, נמחק, הועבר, לא נגיש או בקונפליקט.
- מעקב אחר מקור כל תוכן ששימש את המודל.
- אפשרות Pin, החרגה, Ignore patterns וסיווג מידע רגיש.

מנוע הגרסאות צריך:

- ליצור Snapshot לפני שינוי מאושר.
- לחשב Diff טקסטואלי או בינארי לפי סוג הקובץ.
- להציג Preview לפני החלה.
- לאפשר החלת Patch אטומית, ביטול, Rollback והשוואת גרסאות.
- לזהות שינוי חיצוני מאז הקריאה ולמנוע דריסה שקטה.
- לתמוך ב־Git כאשר קיים Repository, אך לא לדרוש Git.
- לשמור קשר בין Prompt, Run, כלי, Diff, אישור, Commit ותוצאה.
- לנהל Artifacts שנוצרו בנפרד מקבצי מקור, עם גרסאות ו־Provenance.

אבטחת נתיבים:

- למנוע Path Traversal, Symlink Escape, גישה לנתיבי מערכת ושמות התקנים מסוכנים.
- לבצע Canonicalization בצד שמחזיק את הקבצים.
- להגדיר Read-only כברירת מחדל; כתיבה ניתנת לנתיב ולפעולה מפורשים.
- לאפשר רשימות Include/Exclude וסריקת סודות לפני שליחה לספק.
- לא להעביר תוכן או שמות קבצים לענן בלי מסלול עבודה שנבחר במפורש.

### 2.8 שלושה מסלולי עבודה עם קבצים

המשתמש בוחר לכל Workspace, קובץ או פעולה אחד משלושה מסלולים:

| מסלול | היכן נשמר המקור | מה נשלח ל־Gemini | שימוש עיקרי |
|---|---|---|---|
| Gemini Files API | אצל הספק בהתאם למדיניותו | הקובץ או Upload resumable | קבצים שהמשתמש בוחר להעלות לענן |
| אחסון השרת | דיסק או Object Store מקומי של Gemini Nexus | רק קטעים נבחרים או קובץ לפי צורך | ספריית ידע ופרויקטים הנשמרים בשרת |
| תיקייה מקומית בדפדפן | מחשב המשתמש | רק התוכן שהדפדפן אישר והשרת ביקש | עבודה ללא העלאת הפרויקט המלא לשרת |

דרישות משותפות:

- הבחירה מוצגת לפני הפעולה וניתנת לשינוי.
- המערכת אינה משנה מסלול מאחורי הקלעים.
- נשמר Provenance המציין מאין הגיע כל קטע ולאן נשלח.
- קבצים גדולים נקראים ומועברים בזרימה; אין טעינה מלאה לזיכרון.
- העלאה ניתנת לחידוש, לביטול ולאימות hash.
- מחיקה מקומית ומחיקה אצל הספק הן פעולות נפרדות וברורות.
- אין מגבלת מוצר שרירותית על מספר הקבצים, סוגם או גודלם באחסון המקומי.
- קיימות הגנות משאבים הניתנות להגדרה עבור דיסק, זיכרון, זמן, קצב וגודל בקשה כדי למנוע קריסת מערכת.
- מגבלות Gemini אינן הופכות למגבלות האחסון המקומי; השרת מטפל בהן באמצעות Chunking, דחיסה, סיכום, בחירת הקשר, Upload resumable, Batch או פיצול משימות.
- קובץ שאינו נתמך על ידי ספק עדיין ניתן לשמירה, לאינדוקס ולעיבוד מקומי כאשר קיים Parser מתאים.

### 2.9 גישה לתיקייה מקומית דרך הדפדפן

הדפדפן אינו מעניק לשרת גישה ישירה למערכת הקבצים. לכן המסלול המקומי מבוסס על Agent לוגי בתוך לקוח ה־WASM:

1. המשתמש בוחר תיקייה באמצעות File System Access API ונותן הרשאה מפורשת.
2. הדפדפן בונה Manifest ראשוני ושולח לשרת Metadata ו־hashes, לא את כל התוכן.
3. השרת מאנדקס את המבנה ומחליט אילו קבצים או טווחים דרושים.
4. בקשת כלי מ־Gemini מגיעה לשרת ולא ישירות לדפדפן.
5. השרת מעביר לדפדפן בקשת קריאה מצומצמת דרך WebSocket מאומת.
6. הדפדפן בודק שהנתיב נמצא ב־Handle המאושר ומבקש אישור נוסף אם המדיניות מחייבת.
7. הדפדפן מחזיר רק את הבתים או הטווחים שנדרשו.
8. השרת מסנן סודות, מתאים למגבלות הספק ושולח רק הקשר נחוץ.
9. הצעת כתיבה חוזרת כ־Patch; המשתמש רואה Diff ומאשר לפני כתיבה.
10. לאחר כתיבה נוצרת גרסה חדשה ומתבצע אימות חוזר של hash.

יש לתמוך בניתוק ובחיבור מחדש, הרשאות שפגו, Browser שאינו תומך ב־API, שינויי קבצים חיצוניים וטאב שנסגר. אין להבטיח גישה קבועה כאשר הדפדפן או מערכת ההפעלה אינם מאפשרים זאת. המונח המדויק הוא Gemini API; Google AI Studio הוא כלי ניהול ופיתוח ואינו הצד שניגש לתיקייה.

### 2.10 מנוע הקשר וניתוח פרויקטים

- Chunking מותאם שפה ומבנה, לא חיתוך תווים עיוור.
- Parsers לשפות תכנות, Markdown, PDF, מסמכי Office, JSON, CSV, תמונות ואודיו.
- Symbol index, חיפוש מילולי, חיפוש וקטורי וחיפוש היברידי.
- דירוג לפי שאלה, תלות, סמלים, Recency, קבצים פתוחים ושינויים אחרונים.
- Context planner שבונה חבילת הקשר תחת תקציב טוקנים מוגדר.
- שליחה של Diff בלבד כאשר הבסיס כבר ידוע ורלוונטי.
- תקצירים היררכיים שמתעדכנים רק עבור ענפים שהשתנו.
- Prompt cache ו־Semantic cache עם מפתחות הכוללים מודל, הוראות, הרשאות וגרסת מקור.
- מניעת ערבוב מידע בין Workspaces.
- הצגת “מה נשלח למודל” ברמת קובץ, קטע וסיבה לבחירה.
- אפשרות למשתמש להוסיף, להסיר, לנעוץ או לחסום מקור לפני שליחה.
- הערכת טוקנים ועלות לפני ביצוע כאשר הספק מאפשר זאת.
- מודל מקומי קטן אופציונלי לסיווג, ניתוב, Deduplication, סיכום וחיפוש, בלי להחליף אישור משתמש.
- Fallback דטרמיניסטי כאשר Embeddings או מודל מקומי אינם זמינים.

### 2.13 Live

- בחירת התקן ובדיקת עוצמה לפני התחלה.
- תמלול בזמן אמת, השהיה, Mute וחידוש.
- Reconnect עם שמירת Session כאשר הספק תומך.

- מדדי latency, איבוד מקטעים, זמן תגובה ואיכות.
- חלונית צד שניתנת למזעור בזמן עבודה.
- פעולות “הוסף לפרומפט”, “שלח כהודעה”, “שמור כהערה” ו“צור Artifact”.
- שמירה אופציונלית ומפורשת של תמליל או מדיה; ברירת המחדל והמדיניות מוצגות למשתמש.
- טיפול במעבר טאבים, נעילת מסך, החלפת התקן ואובדן הרשאה.

### 2.14 Agents, תכנון ומשימות

- Agent מפרק יעד לתוכנית רב־שלבית ומציג אותה לפני פעולות מסוכנות.
- כל שלב מתועד כ־Run עם קלט, פלט, כלים, הרשאות, עלות ותוצאה.
- משימות ארוכות נשמרות במסד עם Checkpoints וניתנות להשהיה, חידוש וביטול.
- Agent יכול לקרוא Workspace, לחפש, ליצור Patch, להריץ Build/Test ולתקן לפי תוצאות.
- אין כתיבה שקטה: Diff, פקודה והשפעה מוצגים לפי מדיניות האישור.
- קיימות מגבלות צעדים, זמן, עלות, טוקנים, CPU, זיכרון, דיסק ורשת.
- Loop detection, חזרה על כלי, תשובות ריקות וכישלונות חוזרים עוצרים בצורה בטוחה.
- אפשר להעביר שליטה למשתמש בכל שלב ולהמשיך מאותה נקודה.
- התוצאות ניתנות לשחזור: נשמרים גרסאות מקור, קלטי כלים ו־Artifacts.
- מודל Planner ומודל Worker יכולים להיות שונים לפי עלות ויכולת.
- מספר Agents יכולים לעבוד על משימות נפרדות, אך נעילות מונעות כתיבה מתחרה לאותו קובץ או Snapshot.

### 2.15 Sandbox, קוד וניתוח נתונים

- סביבת עבודה מבודדת לכל משימה או Workspace.
- מערכת קבצים וירטואלית עם Mounts מפורשים בלבד.
- Shell, Git, Build ו־Test דרך פקודות Allowlisted או מדיניות אישור.
- מגבלות CPU, זיכרון, זמן, מספר תהליכים, דיסק ופלט.
- רשת חסומה כברירת מחדל; Domain allowlist ואישור מפורש לפתיחה.
- אין העברת סודות אוטומטית לתהליך.
- Snapshot לפני הרצה ו־Cleanup לאחריה.
- קבצי פלט נאספים כ־Artifacts עם MIME, hash ומקור.
- תמיכה ב־CSV/Excel, טבלאות, גרפים ודוחות.
- Preview בטוח ל־HTML ומסמכים בלי לאפשר גישה ל־Origin הראשי.
- לוגים ו־Exit Code נשמרים וניתנים לצפייה.
- Code Execution אינו רץ בתוך תהליך השרת הראשי.
- יש לתמוך ב־WASI/Wasmtime לכלים קטנים וב־Sandbox תהליכי או Container למשימות מלאות, בהתאם לסביבת היעד.

### 2.16 כלים, Plugins ו־Connectors

כל כלי מוגדר באמצעות Manifest הכולל שם, גרסה, Schema, הרשאות, זמן מרבי, קלט/פלט, hash וחתימה אופציונלית.

יעדים:

- Registry מקומי לגרסאות, התקנה, עדכון, השבתה ו־Rollback.
- סביבת פיתוח ובדיקת כלי לפני הפעלה.
- יצירת Plugin מפרומפט כתהליך שמפיק מקור, בונה, בודק ומבקש אישור התקנה.
- הרשאות גרנולריות לקבצים, רשת, Secrets, GPU ותהליכים.
- Tool catalog מצומצם לפי המשימה כדי לחסוך טוקנים.
- Validation מלאה של Function Calls לפני ביצוע.
- Idempotency לפעולות שניתנות לחזרה.
- תוצאות גדולות נשמרות כ־Artifact והמודל מקבל תקציר או Handle.

Connectors מתוכננים:

- GitHub: Repository, Branch, Commit, Diff, Pull Request ו־Issues.
- Google Drive ו־OneDrive: בחירת קבצים, קריאה, כתיבה וגרסאות.
- Connectors נוספים דרך Broker אחיד.

כל Connector דורש OAuth מתאים, אחסון Token מוצפן, Scopes מינימליים, Revoke, Audit והצגת יעד הפעולה. אין למסור אסימון חיצוני למודל או לתוסף.

### 2.17 תזמור, תורים ועמידות

- תור מתמשך במסד הנתונים ו־Outbox טרנזקציוני.
- Idempotency key לכל בקשה משנת מצב או פעולה חיצונית מתאימה.
- Lease, heartbeat ותביעת עבודה אטומית.
- Retry עם Backoff ו־Jitter רק לשגיאות בטוחות לחזרה.
- Dead-letter או מצב Failed מפורט לפעולות שאינן ניתנות לחזרה.
- ביטול שיתופי שמגיע לספק, לכלים ול־Sandbox ככל האפשר.
- מגבלת מקביליות גלובלית, לפי Workspace, לפי ספק ולפי משאב.
- סדר אירועים מונוטוני ויכולת Replay ל־SSE.
- Backpressure באמצעות Channels/Pipelines בלי באפרים בלתי מוגבלים.
- שמירת תשובה חלקית ואבחנה בין Resume display לבין יצירת בקשת ספק חדשה.
- תמיכה עתידית במספר מופעי שרת באמצעות PostgreSQL ונעילות, בלי לפגוע במצב היחידני הפשוט.
- פעולות על אותו קובץ או שיחה משתמשות ב־Optimistic Concurrency או נעילה ממוקדת.

### 2.18 נתונים, אחסון ו־Artifacts

- SQLite הוא ברירת המחדל למופע יחיד; PostgreSQL נתמך לסביבה הדורשת עמידות או Scale-out.
- סכימה ממוספרת, Migrations קדימה, בדיקת גרסה ב־readiness וגיבוי לפני שדרוג מסוכן.
- אחסון Blobs מופרד מ־Metadata וניתן להעברה בין דיסק מקומי ל־Object Store.
- Content-addressed storage ו־hashes מונעים כפילויות כשמתאים.
- הצפנה במנוחה לסודות ולמידע רגיש.
- מדיניות שימור נפרדת לשיחות, אירועים, קבצים, Artifacts, Snapshots ו־Audit.
- Garbage collection אינו מוחק Blob שעדיין קיימת אליו הפניה.
- ייצוא מלא בפורמט מתועד ויכולת שחזור למופע נקי.
- בדיקת Restore תקופתית היא חלק ממוכנות פרודקשן.
- מחיקה מציגה מה יימחק מקומית, מה יישאר בגיבוי ומה דורש מחיקה נפרדת אצל ספק חיצוני.

### 2.19 יעילות טוקנים, זמן ועלות

- אין הבטחה ל“אפס טוקנים” כאשר Gemini נדרש; המטרה היא לשלוח את המינימום שמספיק לתוצאה נכונה.

- Context budget מוקצה לפי סוג משימה ולא רק לפי מספר סבבים.
- היסטוריה ישנה מסוכמת היררכית עם אפשרות לעיין במקור.
- Repository map, Symbol index ו־Dependency graph מחליפים שליחת פרויקט שלם.
- קבצים ללא שינוי אינם נשלחים שוב כאשר Cache תקף.
- סכימות קבועות, Tool schemas קצרים ותגובות מובנות מצמצמים ניסיונות חוזרים.
- Router בוחר מודל קטן למשימות סיווג וסיכום ומודל חזק רק כשנדרש.
- Batch משמש לפעולות לא דחופות כאשר הוא זול או יעיל יותר.
- המשתמש רואה הערכת עלות, שימוש בפועל וחריגה מההערכה.
- תקציבים ניתנים להגדרה לריצה, יום וחודש, עם Soft warning ו־Hard stop אופציונלי.

### 2.20 ביצועים וטכנולוגיות .NET

יעד הפלטפורמה הוא הגרסה העדכנית שנבחרה לפרויקט, עם מעבר ל־.NET 11 ו־C# 15 כאשר Toolchain יציב וזמין לבנייה ול־CI. עד להשלמת המעבר, ה־README חייב להבחין בין יעד זה לבין .NET 10/C# 14 הקיימים.

יעדי ביצועים:

- Zero-allocation ב־Hot Paths שנמדדו, לא כהצהרה גורפת על כל UI.
- `Span<T>`, `ReadOnlySequence<T>`, `ArrayPool<T>`, `MemoryPool<T>` ו־Pipelines לזרימה.
- Channels חסומים, `ValueTask` כאשר רוב ההשלמות סינכרוניות, ו־Cancellation לאורך כל הצינור.
- `FrozenDictionary`, `FrozenSet` ו־`SearchValues` לנתונים יציבים.
- SIMD ו־Intrinsics רק עם Benchmark ו־fallback נכון.
- `System.Text.Json` source generation, `LoggerMessageAttribute`, MemoryPack ו־Mapperly במקום Reflection במסלולי מוצר הנשלטים על ידינו.
- NativeAOT לשרת Linux כאשר כל התלויות תואמות.
- WASM AOT/Mono/LLVM לפי תמיכת הפלטפורמה ומדידות גודל/זמן.
- Dapper.AOT או EF Core compiled queries למסלולי נתונים חמים; הבחירה לפי שאילתה ולא לפי רשימת חובה.
- FastEndpoints עבור API, Refit רק ללקוחות HTTP מתאימים, Polly לעמידות, gRPC רק כאשר הוא מוסיף ערך פנימי מדיד.
- `NativeMemory`, `Unsafe`, `Interlocked`, `SpinWait`, `Lock`, `SpinLock` ו־`SemaphoreSlim` רק ברכיבים נמוכי־רמה עם בדיקות Race, גבולות בעלות ותיעוד.
- Interop דרך `LibraryImport`; זיכרון מוצמד לזמן הקצר ביותר.
- GPU אופציונלי דרך OpenCL/CUDA, ILGPU, Silk.NET או ComputeSharp בהתאם לפלטפורמה, עם CPU fallback.
- אין Reflection בקוד מוצר חם; Reflection פנימי שאינו בשליטתנו ב־Blazor יתועד ויישאר מחוץ למסלולים קריטיים.
- Benchmarks מגדירים תקציבי latency, הקצאות, Throughput וגודל Binary ומונעים Regression משמעותי.

### 3.1 התחברות מקומית

ב־PowerShell יש לתת אמון באישור הפיתוח ולהריץ פעם אחת את סקריפט ההגדרה. הסקריפט יוצר בשורש המאגר קובץ מקומי יחיד בשם `nexus.settings.json`; הקובץ מוחרג מ־Git ומכיל את כתובת השרת, פרטי המנהל, מפתח Gemini, מסד הנתונים והמגבלות:

```powershell
dotnet dev-certs https --trust
./scripts/Initialize-Development.ps1 -AdminPassword "103755" -GeminiApiKey "מפתח-Gemini"
dotnet run --project ./GeminiNexus.Server --launch-profile https
```

לאחר מכן פותחים `https://localhost:5000/` ונכנסים בשם המשתמש `admin` ובסיסמה שנכתבה לקובץ. ממשק ה־Web הוא ברירת המחדל ב־`/`, ה־API נמצא ב־`/api`, והנתיבים `/web` ו־`/wasm` מפנים אל הממשק. כולם רצים תחת אותו HTTPS ואותו פורט, ולכן אין צורך להפעיל שרת WASM נפרד. במצב Development מקומי ניתן להשתמש בסיסמה בת 6 תווים; בכל סביבה אחרת עדיין נדרשים לפחות 16 תווים.

ב־Visual Studio יש להגדיר את `GeminiNexus.Server` כ־Startup Project ולבחור בפרופיל `https`. לפרויקט `GeminiNexus.Client.Wasm` אין פרופיל הרצה עצמאי; הוא נבנה כחבילת הדפדפן ומוגש דרך השרת בלבד.

בהרצת Development השרת טוען במפורש את Static Web Assets של Client.Wasm, ולכן `Start` מתוך Visual Studio חייב להציג את סביבת העבודה ב־`https://localhost:5000/` ולא תשובת 404. ה־CI מפעיל גם את מסלול האירוח הזה ובודק את `index.html` ואת נכס ה־`_framework` בעל השם המוטבע שאליו הוא מפנה.

אפשר גם להעתיק ידנית את `nexus.settings.example.json` ל־`nexus.settings.json` ולערוך אותו. כדי להשתמש בקובץ במקום אחר מגדירים `NEXUS_CONFIG` לנתיב המלא שלו. משתני סביבה ופרמטרים משורת הפקודה גוברים על הקובץ.

הרצה ישירה ללא פרופיל משתמשת גם היא ב־HTTPS/5000:

```powershell
dotnet run --project ./GeminiNexus.Server --no-launch-profile
```

PowerShell:

```powershell
./scripts/Publish.ps1
python ./tests/integration.py
python ./tests/source_checks.py
python ./tests/load.py
```

Bash:

```bash
bash scripts/publish.sh
python3 tests/integration.py
python3 tests/source_checks.py
python3 tests/load.py
```

הסקריפטים בונים את Client.Wasm לתיקייה זמנית ומעתיקים אותו אל `wwwroot` של השרת, כך שתוצר הפריסה היחיד הוא `artifacts/publish/server`. בדיקות האינטגרציה מפעילות שרת אמיתי מול ספק בדיקה מקומי, עם נתונים וסודות זמניים, ללא קריאות Google בתשלום. בדיקות המקור מקמפלות את החוזים, רכיבי Razor ומתאם הספק ומריצות בדיקות SSE, סריאליזציה, השחרה ו־Markdown; הן אינן תחליף לבדיקות מסד הנתונים או לפרסום WASM מלא.

תהליך GitHub Actions בקובץ `.github/workflows/verify.yml` כולל פרסום NativeAOT, בדיקות אינטגרציה מול הקובץ הטבעי, PostgreSQL בשני מופעי שרת, פרסום הממשק, בדיקות עומס ומקור ובדיקת קבלה בדפדפן.

## 4. פריסה מאוחדת

1. לבטל את מפתחות Gemini שהיו בגרסאות הישנות וליצור מפתחות חדשים. הסרתם מקובצי המקור אינה מבטלת את המפתחות או מוחקת היסטוריית Git.
2. להגדיר `Auth__AdminPasswordFile` ו־`Gemini__ApiKeyFile` לקבצים חיצוניים, או את `Auth__AdminPassword` ו־`Gemini__ApiKey` בסביבת התהליך. סיסמת המנהל חייבת להכיל לפחות 16 תווים. אין לשמור ערכים אלה במאגר. אין לשתף אותם בצ׳אט.
3. להריץ את `scripts/Publish.ps1` או `scripts/publish.sh`. הסקריפטים בונים את שרת Linux כ־NativeAOT, את ספריית C++ ואת WASM, ומאחדים אותם בתוך `artifacts/publish/server`. יש להעתיק רק תיקייה זו אל `/srv/gemininexus/server`.
4. להתאים ב־`deploy/server.env.example` את `AllowedHosts` ואת נתיבי הסודות, וליצור קובץ `/etc/gemininexus/server.env` עם הרשאות שירות בלבד. ב־`deploy/gemininexus.service` להתאים את הנתיב ל־dotnet ואת משתמש השירות. ליצור משתמש שירות ייעודי לפני התקנה.
5. השרת, ה־API וקובצי ה־WASM פועלים יחד על פורט 5000. TLS ציבורי והפניית 443 אל 5000 מוגדרים מחוץ למאגר. אם קיים Reverse Proxy, יש לרשום רק את כתובתו תחת `Proxy__KnownProxies__0`; אין לסמוך על כל Proxy.
6. להפעיל את השירות ולבדוק `/health/ready`, התחברות, שיחה ורענון דפדפן דרך הדומיין וה־HTTPS האמיתיים.
7. לגבות את מסד הנתונים ואת `Auth:KeyPath` באחסון מוגן. ב־SQLite יש להשתמש ב־Online Backup או לעצור את השירות ולגבות את המסד עם קובצי WAL/SHM. לפני פתיחת השירות למשתמשים יש לבצע שחזור ניסיון.

השרת דורש HTTPS בפרודקשן. `Auth:AllowInsecureLocal=true` מותר רק ב־Development או Testing. אין עקיפת אישורי TLS.

אפשר ליצור משתמשים ולנתק את כל המכשירים שלהם בחלונית ״חשבון ואבטחה״. יצירת משתמש נוסף זמינה גם דרך `POST /api/admin/users` עם `{name,password}` מתוך סשן מנהל ועם כותרת `X-Nexus-Request: 1`. סיסמת המנהל מהסביבה מעודכנת בעת אתחול; שינוי שלה מבטל את סשני המנהל, ואתחול ללא שינוי משמר אותם. משתמש רגיל יכול לשנות סיסמה בחלונית החשבון באמצעות הסיסמה הקיימת; הפעולה מבטלת את כל החיבורים הקודמים. סשן תקף לשבעה ימים לכל היותר, ונבדק מול המסד בכל בקשה. איפוס בדוא״ל זמין למשתמשים רגילים כאשר מוגדר ספק SMTP או pickup directory; סיסמת המנהל נשארת מנוהלת בסוד השרת.

## 5. גבולות מוכנות והשלמות נדרשות

המימוש אינו מסומן כפרודקשן מלא עד שכל הבדיקות וההשלמות הרלוונטיות הסתיימו:

| תחום | מה עדיין נדרש |
|---|---|
| אימות סביבת היעד | בנייה מלאה עם חבילות משוחזרות, בדיקות בדפדפן על WASM אמיתי, בדיקת Gemini אמיתי, דומיין ו־TLS, גיבוי ושחזור |
| גלילה וזיכרון | בדיקת עומס עם מדיה והודעות בגבהים משתנים; הודעה בודדת ומדיה עשויות לחרוג מבאפר התצוגה |
| PostgreSQL וריבוי שרתים | הקוד וה־CI כוללים הגירות ממוספרות ובדיקת תחרות בשני תהליכים; עדיין נדרשת הרצה מוצלחת של ה־CI החדש ובדיקת גיבוי/שחזור מול מסד היעד |
| API מתקדם | קיים מסך פעולות מאוחד ושער Live; לכל יכולת נשמרים הבקשה, התגובה והסטטוס. עדיין נדרש אימות מול חשבון Gemini חי מפני שהבדיקות המקומיות משתמשות בספק מדומה |
| כלים ותוספים | קיימים function calling רב־סבבי וחבילות WASI מבודדות. יש לאמת `wasmtime` וחבילה אמיתית במערכת היעד; הרשאות רשת וקבצים אינן ניתנות כברירת מחדל |
| AOT וביצועים | שרת NativeAOT, בדיקות אינטגרציה טבעיות, בדיקת עומס ומסלול SIMD ללא הקצאות קיימים. `Client.Wasm` עדיין מפעיל fallback של Reflection לצורכי JS interop פנימי של Blazor 10; לכן איסור Reflection מוחלט בכל ארבעת הפרויקטים אינו תואם כרגע ל־Blazor שנבחר |
| ספריות וחישוב מקומי | MemoryPack,‏ FastEndpoints,‏ Polly,‏ Dapper.AOT,‏ `System.Text.Json` source generation,‏ C++/NativeMemory/SIMD/OpenCL משולבים. Refit,‏ Mapperly,‏ gRPC,‏ EF compiled queries,‏ Rust,‏ ILGPU/CUDA ו־bflat אינם משולבים מפני שאין להם כרגע תפקיד תפעולי שאינו משכפל את מתאמי HTTP/ADO/OpenCL הקיימים |
| תפעול משתמשים | איפוס סיסמה, שימור, גיבוי/שחזור ומבחן עומס קיימים; ניטור חיצוני, תרגיל שחזור תקופתי וספק SMTP אמיתי תלויים בסביבת הפריסה |

היסטוריית הודעות אינה נמחקת כשמפנים את באפר הלקוח. אירועי הדיבאג כפופים ל־`Limits:TraceRetentionDays`; זרם אירועים שכבר נמחק נסגר באופן תקין. השדות הגולמיים משמרים מידע שהספק מחזיר, לאחר השחרת שדות סוד מוכרים; אין גישה למידע שהספק לא חשף.

מפת הפיצ׳רים המומלצת להמשך נמצאת ב־[`docs/GEMINI_FEATURE_ROADMAP.md`](docs/GEMINI_FEATURE_ROADMAP.md).

מקורות: [API של Google](https://ai.google.dev/api/generate-content), [תיעוד החשיבה של Gemini](https://ai.google.dev/gemini-api/docs/thinking).

## 6. אימות השינויים

- קו הבסיס שלפני הסרת MAUI עבר את כל ארבעת מסלולי GitHub Actions.
- סביבת ‎.NET 10 כוללת ארבעה פרויקטים, בדיקות מקור, PostgreSQL ונתיבי ברירת המחדל של בדיקות האינטגרציה.
- השרת מארח גם את Client.Wasm, כך שהרצה מ־Visual Studio או `dotnet run` משתמשת במקור אחד להתחברות ול־API.
- מצב האימות המחייב הוא ריצת GitHub Actions האחרונה של `master`; אין להסתמך על מזהי ריצות ישנים לאחר שינוי קוד.
- פריסה לשרת יעד, שינוי DNS, החלפת מפתחות אצל Google ובדיקה עם Gemini חי מחייבים את חשבונות וסביבת היעד.
